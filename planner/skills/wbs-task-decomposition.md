# WBS任务拆解模板

> 用途：planner 执行任务规划时的标准拆解工具
> 使用场景：任何需要将大任务拆解为小任务的工作

## 使用方法

1. 读取 `mission.md` 或用户需求
2. 按本模板格式输出 WBS
3. 检查每个任务是否有依赖关系
4. 标注可并行的任务组

## WBS拆解规范

### 拆解原则

- 每个任务必须有明确的输出物
- 每个任务时长不超过 2小时（否则继续拆分）
- 任务必须有明确的完成标准
- 识别"dummy task"（为了填充而存在、无实际产出的任务）

### 拆解步骤

```
STEP 1: 识别任务阶段（phases）
  → 每个阶段有明确的开始和结束条件

STEP 2: 识别每阶段的子任务（tasks）
  → 子任务是完成阶段所需的最小单元

STEP 3: 识别任务依赖
  → 必须先完成后才能开始的任务 → 串行
  → 可以同时进行的两组任务 → 并行

STEP 4: 工时估算
  → 乐观 / 最可能 / 悲观 三点估算
  → 最终工时 = (乐观 + 4×最可能 + 悲观) / 6

STEP 5: 识别风险点
  → 哪些任务最可能延期
  → 哪些任务依赖外部输入
```

## 输出格式

```markdown
## WBS 任务分解结构

### 阶段1：[阶段名称]
| 任务ID | 任务名称 | 输出物 | 时长 | 依赖 | 并行组 |
|--------|---------|--------|------|------|--------|
| P1-T1 | ... | ... | 0.5h | - | A |
| P1-T2 | ... | ... | 1h | P1-T1 | A |

### 阶段2：[阶段名称]
...

### 风险清单
| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| ... | 高 | 高 | ... |
```

## STEP 0 头脑风暴（强制5问）

在拆解之前，必须先自问：

1. **解法路径有哪些？** （至少3种）
2. **忽略的风险？** （至少2个）
3. **与历史任务的差异？** （参考了什么？）
4. **时间压缩时牺牲什么？** （优先级排序）
5. **协作中最容易在哪卡住？** （预防措施）

## 检查清单

完成WBS后，自检：

- [ ] 每个任务有明确输出物
- [ ] 每个任务时长 ≤ 2小时
- [ ] 依赖关系已标注
- [ ] 并行组已分组
- [ ] 风险清单已识别
- [ ] STEP 0 五问已回答
- [ ] 工时估算有三点数据
