# Clarification Question Generator

> 用途：clarifier 生成澄清问题时使用的标准模板
> 使用场景：置信度 < 0.85 时，必须追问

## 使用方法

1. 评估任务置信度
2. 如果 < 0.85，按本模板生成澄清问题
3. 问题数量 = 置信度差距 × 10（置信度0.6 → 问2-3个问题）

## 问题分类

### A. 需求范围类

| 问题模板 | 适用场景 |
|---------|---------|
| 「需要覆盖的范围是？」 | 任务边界模糊 |
| 「哪些是必须做的，哪些是可选的？」 | 优先级不清 |
| 「做这个和做那个，优先级怎么排？」 | 多目标冲突 |

### B. 约束条件类

| 问题模板 | 适用场景 |
|---------|---------|
| 「预算大概多少？」 | 没有金额范围 |
| 「时间上有什么硬性截止吗？」 | 没有截止时间 |
| 「有没有不能用的技术/工具/平台？」 | 技术栈限制 |
| 「对质量的要求是什么程度？」 | 质量标准模糊 |

### C. 交付物类

| 问题模板 | 适用场景 |
|---------|---------|
| 「最终交付什么格式？」 | 交付格式不清 |
| 「谁来用这个产出？」 | 受众不明 |
| 「成功标准是什么？」 | 验收条件模糊 |
| 「需要给谁汇报？」 | 汇报对象不清 |

### D. 背景类

| 问题模板 | 适用场景 |
|---------|---------|
| 「这是为了解决什么问题？」 | 动机不清 |
| 「之前有没有尝试过？结果如何？」 | 有历史参考 |
| 「为什么现在要做这个？」 | 时机不明 |

## 澄清问题输出格式

```markdown
## 澄清问题

### 问题1：[类型] <问题>
- 原因：<为什么这个问题很重要>
- 回答后对置信度的影响：预计提升至 0.XX

### 问题2：...
```

## 置信度评估表

| 置信度 | 含义 | 动作 |
|--------|------|------|
| 0.9-1.0 | 完全清晰 | 直接推进 |
| 0.8-0.9 | 比较清晰 | 小疑问可记录，推进 |
| 0.6-0.8 | 部分模糊 | 必须追问2-3个核心问题 |
| 0.4-0.6 | 严重模糊 | 暂停，等用户回复 |
| < 0.4 | 完全不明确 | 强烈建议暂停，明确需求前不动手 |

## 快速决策规则

**置信度 ≥ 0.85？**
- YES → 直接推进，记录小疑问供 analyzer 参考
- NO → 列出必须追问的问题，等待回复后再推进

**最多问几个问题？**
- 置信度 0.7-0.85：最多问2个核心问题
- 置信度 0.5-0.7：问3-5个问题
- 置信度 < 0.5：建议暂停，不要盲目推进
