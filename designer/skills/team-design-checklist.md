# Team Design Checklist

> 用途：designer 设计执行团队时的标准检查清单
> 使用场景：每个任务的团队设计前，必须逐项检查

## 使用方法

1. 读取 planner 的 WBS 和 analyzer 的复杂度评估
2. 按本 checklist 逐项检查
3. 输出团队设计配置

## 设计前自问

在开始设计团队之前：

1. **需要几个人？**
   - 少于等于3人 → 单Agent可能更高效
   - 多于3人 → 需要明确的协调角色

2. **需要哪些专业能力？**
   - 列出WBS中所有任务所需的专业类型
   - 例：代码开发 / UI设计 / 文案撰写 / 数据分析 / 风险评估

3. **有没有可以并行的子任务？**
   - 并行 = 需要多个Agent同时工作
   - 串行 = 必须等待上游完成

4. **有没有高风险子任务？**
   - 高风险 → 需要reviewer角色介入

5. **预算/时间约束是什么？**
   - 时间紧 → 减少Agent数量，减少沟通开销
   - 时间充裕 → 可以增加Agent并行度

## Team Design Checklist

完成团队设计后，逐项检查：

### 角色检查

- [ ] **每个角色有明确的职责边界**
  - 没有两个角色做同样的事
  - 没有任务无人认领

- [ ] **每个角色的输入输出已定义**
  - 明确谁给谁什么
  - 明确交付标准

- [ ] **角色数量合理**
  - 最少2人（执行+审核）
  - 最多8人（超出则考虑分组）

### 协作检查

- [ ] **并行任务有独立Agent**
  - 如果两个任务同时进行，需要两个Agent

- [ ] **依赖关系已标注**
  - A完成 → B才能开始
  - 不能有循环依赖

- [ ] **交接点已明确**
  - 在哪里交接
  - 交接什么格式

### 风险检查

- [ ] **单点故障已识别**
  - 如果某个Agent缺席，任务能否继续？
  - 有没有备份方案？

- [ ] **沟通成本已评估**
  - Agent越多，沟通成本越高
  - N个Agent有 N×(N-1)/2 条沟通路径
