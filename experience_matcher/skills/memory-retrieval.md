# Memory Retrieval Guide

> 用途：matcher 在检索历史经验时的标准流程
> 位置：matcher/skills/memory-retrieval.md

## 使用方法

每次任务进入 matcher 阶段时：

1. 读取任务的基本信息（task_type, domain, constraints）
2. 按本流程检索 memory/ 和 knowledge/entries/
3. 输出匹配度评估和可复用清单

## 检索路径

```
memory/                      # Agent记忆（长期）
  └── YYYY-MM-DD.md         # 按日期分

knowledge/
  └── entries/              # 经验文档（RAG）
      └── YYYY-MM-DD-*.md   # 经验条目

templates/                   # 模板库
```

## 检索步骤

### STEP 1: 关键词检索

根据任务领域，提取3-5个关键词：

```
例：活动策划 → ["迎新", "社团", "预算", "线下", "流程"]
例：网页开发 → ["前端", "动画", "GSAP", "单页"]
例：数据分析 → ["Python", "pandas", "可视化", "报告"]
```

### STEP 2: 扫描日期范围

优先检索最近3个月的经验：
- 最近30天：直接可用
- 30-90天：需要验证时效性
- 90天以前：可能已过时

### STEP 3: 匹配度评分

四维度打分：

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 类型匹配 | 30% | 同类型任务（代码/策划/分析） |
| 复杂度匹配 | 25% | 规模相近（大小/时长/资源） |
| 领域匹配 | 25% | 行业/场景相同 |
| 约束匹配 | 20% | 限制条件相似 |

**总分 = Σ(维度分 × 权重)**

### STEP 4: 分类输出

| 匹配度 | 决策 | 操作 |
|--------|------|------|
| ≥ 80% | **直接复用** | 复制模板，调整参数 |
| 60-80% | **微调复用** | 引用部分，补充新内容 |
| < 60% | **从零设计** | 不引用，作为参考 |

## 输出格式

```markdown
## 经验检索报告

### 关键词
- ...

### 检索结果
| 经验ID | 日期 | 匹配度 | 可复用部分 | 不可复用部分 |
|--------|------|--------|----------|------------|
| exp_001 | 2026-04 | 75% | 预算分类框架 | 具体数字需调整 |

### 匹配度计算
- 类型匹配：75%（都是活动策划）
- 复杂度匹配：60%（规模不同）
- 领域匹配：90%（都是社团）
- 约束匹配：70%（都有预算约束）
- **综合匹配度：75% → 微调复用**

### 可复用清单
- [ ] 预算分类模板
- [ ] 人员分工框架
- [ ] 风险清单模板

### 不可复用（需新做）
- 活动时间线（每年时间不同）
- 具体预算数字（每年物价不同）
```

## 检索优先级规则

1. 同项目优先（同一个项目的不同版本）
2. 同领域优先（社团活动 > 企业活动）
3. 近日期优先（3个月内 > 6个月内）

## 常见错误

- ❌ 只看标题就判断匹配度
- ❌ 忽略约束条件的差异
- ❌ 直接复制具体数字（应该只复制结构）
- ❌ 不更新知识库（做完任务不写经验）
