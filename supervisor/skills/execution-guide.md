# Execution Guide

> 用途：supervisor 调度执行时的标准流程
> 版本：v1.0

## 执行前检查

在启动执行之前，supervisor 必须确认：

- [ ] orchestrator 已完成工作区编排（06_orchestrated.json 存在）
- [ ] 所有前置 Agent 的状态文件已就绪
- [ ] 团队成员清楚自己的任务和交付标准
- [ ] 应急通讯方式已建立（至少知道找谁）

## 执行监控流程

```
启动执行
    ↓
监控每个 Agent 的进度
    ↓
每完成一个阶段 → 评分
    ↓
评分 < 60 → 触发回退
    ↓
所有阶段完成 → 最终评分
    ↓
交付 archivist
```

## 评分触发机制

| 触发条件 | 动作 |
|---------|------|
| 单 Agent 产出 < 60 | 回退该 Agent，最多3次 |
| 某阶段延期 > 50% | 警告，可能需要调整计划 |
| 发生阻塞 > 30 分钟 | 必须报告，可能需要人工介入 |

## 回退执行规范

### 触发条件
评分 < 60 分

### 回退流程

```
1. 识别问题 Agent
2. 读取 reviewer 的 hint
3. 通知该 Agent 返工（附 hint）
4. 记录回退次数
5. 重新执行
6. 再次评分
```

### 回退限制

- 单个 Agent 最多回退 **3次**
- 超过3次仍 < 60 → 触发**升级人工**
- 升级人工时，必须写明：问题描述 + 已尝试的解决方案 + 当前障碍

## 四维评分规范

每次评分必须覆盖4个维度：

| 维度 | 权重 | 含义 |
|------|------|------|
| 完整性 | 30% | 是否包含所有要求的产出 |
| 准确性 | 30% | 产出内容是否正确 |
| 可执行性 | 25% | 产出是否可以直接使用/执行 |
| 规范性 | 15% | 格式/文档结构是否符合标准 |

## 输出格式

```json
{
  "status": "executed",
  "score": <总分>,
  "checks": [
    {
      "dimension": "完整性",
      "score": <分>,
      "evidence": "<评分依据>"
    }
  ],
  "agent_scores": {
    "<agent_id>": <分>
  },
  "rollback_count": <N>,
  "issues": ["<问题描述>"],
  "escalation": {
    "triggered": false,
    "reason": null
  }
}
```

## 风险预警规范

以下情况必须发出预警：

1. **进度风险**：某阶段完成时间 > 预计 × 1.5
2. **资源风险**：人员/设备/工具不可用
3. **质量风险**：某 Agent 连续2次评分在 60-70 之间

预警格式：

```markdown
## 风险预警 [级别：高/中/低]

**问题描述**：...
**影响**：...
**建议措施**：...
**上报**：是否需要人工介入？
```
